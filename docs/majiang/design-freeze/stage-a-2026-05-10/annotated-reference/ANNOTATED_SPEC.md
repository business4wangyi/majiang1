# 竞品图标注冻结规格（给编码 agent）

依据：
- `AGENTS.md`
- `docs/standards/rules/development.md`
- `docs/majiang/WEB_UI_PRODUCT_INTERACTION_DESIGN.md`（13.0/13.3/14.0）
- `docs/majiang/FOLDER_STRUCTURE.md`

## 1) 结构比例（桌面）
1. 桌心主舞台（A）：`58%~64%` 视觉面积。
2. 侧栏信息区（E）：`<=16%` 视觉权重，默认弱化。
3. 底部手牌区（D）+主动作区（G）：总高度 `24%~30%`。
4. 左右座位区（B/C）：信息压缩显示，不可替代桌心主链路。

## 2) 结构比例（移动）
1. 顶部摘要（M1）：`10%~14%`。
2. 中部桌心（M2）：`32%~40%`。
3. 手牌区（M3）：`18%~24%`。
4. 主动作区（M4）：`8%~12%`，紧贴手牌区。

## 3) 主链路冻结
- 必须可直读：`谁打牌 -> 目标牌 -> 我可响应 -> 主动作`。
- ResponseWindow 默认强主动作固定为 `过`。
- PlayerTurn 默认强主动作固定为 `出牌`。

## 4) 结果页冻结
- 固定四层：`结果类型 -> 角色关系 -> 分数变化 -> 下一步入口`。
- 四类型 `tsumo/ron/draw/abort` 均需同结构，不可缺层。

## 5) 编码可验收约束（10条）
1. 桌面首屏先读 A，不得让 E 抢主视觉。
2. 移动端 M3/M4 必须在单手可达区。
3. 主动作区只允许一个强主动作。
4. 次级动作进入折叠或次级按钮，不长期并列。
5. 目标牌高亮至少高于牌河一个对比层级。
6. 手牌选中态必须有位移+描边双反馈。
7. 提交失败必须恢复可操作并保留上下文牌。
8. 结果页必须解释“谁赢/为什么/分数如何变化”。
9. 诊断入口默认弱化，仅展开后展示完整层级。
10. 不重写核心规则，不改 CLI 路径。

## 6) 阶段A判定（当前）
- 作为“竞品对齐输入”通过。
- 作为“最终高保真成品图”仍待后续实现稿对齐验证。
