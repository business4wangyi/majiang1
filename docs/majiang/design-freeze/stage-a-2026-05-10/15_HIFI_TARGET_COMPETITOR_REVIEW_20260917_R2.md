## 给编码 agent 的改稿单
> 本轮对象已可进入**视觉落地拆解**；实现须遵守下方约束，不可把圆形浮钮当最终 UI 规范。

- 保留：
  - 四方微透视深绿桌 + 实体牌系统
  - 中心风位/余牌/四向分盘 + 右缘方向脉冲意图
  - 右家牌河内目标牌局部光效（无教学箭头/气泡/说明条）
  - 角区稀疏：头像 + 风位/名称 + 分数；底部仅保留轻量「可胡」
  - 固定局势与中文广东术语；`胡` > `过` > `碰/杠`
- 修改：
  1. **作用范围**：底部动作层形态（实现层）  
     **具体改动**：落地时不要照抄本图圆形浮钮；做成接近 Riichi City 的胶囊/印章字效条（厚描边、渐变、轻微 bloom），`胡` 面积与亮度仍唯一最强。  
     **验收条件**：实现截图与 `steam-shot-2.jpg` 并排时，动作层同类为「游戏字效条」而非「四颗圆钮 HUD」。  
     **禁止扩展**：不重回深色矩形 Web 工具条；不引入日式术语。
  2. **作用范围**：目标牌 ↔ 中心盘右缘链路（实现微交互）  
     **具体改动**：保持弱高亮语言（牌光效 + 中心盘右缘脉冲 + 座位轻高亮）；禁止加回大斜向箭头/说明气泡/桌心说明条。  
     **验收条件**：无说明文案时 3 秒内可读「右家打出 → 可胡 → 按胡」。  
     **禁止扩展**：不新增第二套教学引导 UI。
  3. **作用范围**：角区信息密度（实现约束）  
     **具体改动**：默认只渲染头像 + 分数 + 至多一个短状态；勿恢复多座位并列「可胡/当前出牌」标签墙。  
     **验收条件**：桌心主舞台观感 ≥ 约 55%。  
     **禁止扩展**：不重做整套角色系统。
- 验证：
  - 编码落地后桌面截图再跑档位 B 并排审
  - 核对固定局势与术语硬约束（`13_…BRIEF`）
  - 移动端 390×844 同局势补目标帧后再审移动门槛
- 禁止：
  - 用现有 `web-ui-prototype` CSS 微调冒充已达成本图
  - 用 acceptance 11/11 替代视觉通过
  - 把打回稿 `…-review-rejected-20260917.png` 当效果图交付

## 符合项
- 说明型叠加层已移除：无大斜向箭头、无「右家打出」气泡、无桌心「右家打出，可胡」说明条
- 首眼链路改为牌光效 + 桌心结构 + 主动作自解释
- 角区信息密度明显下降，桌心张力回升
- 实体牌 / 中心盘 / 四家座位骨架与竞品同属商业局内桌面
- `胡` 视觉权重无可争议地高于 `碰/杠/过`

  影响：若编码照抄圆钮，会固化次优 HUD；不阻止以本图为桌面骨架开工。
