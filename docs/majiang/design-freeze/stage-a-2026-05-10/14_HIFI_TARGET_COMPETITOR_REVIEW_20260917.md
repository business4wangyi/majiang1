## 给编码 agent 的改稿单
> 本轮对象是**目标图重绘**，不是前端 CSS。未通过前禁止派编码实现。

- 保留：
  - 四方桌心 + 微透视深绿桌布 + 实体牌系统方向
  - 中心风位/余牌/四向分数盘结构
  - 四家头像座位位
  - 固定局势「右家打出 → 可胡」与中文广东术语（无荣和/立直/听牌）
  - `胡` 为主、`过` 次、`碰/杠` 弱层级的动作信息架构意图
- 修改：
  1. **作用范围**：响应链路视觉语言（目标牌 ↔ 桌心 ↔ 主动作）  
     **具体改动**：删除大斜向教学箭头、气泡「右家打出」、桌心下方说明条「右家打出，可胡」等说明型叠加层；改为竞品式弱高亮——目标牌局部光效/轻微抬升 + 中心盘右缘方向脉冲 + 底部 `胡` 自解释。文字仅允许极短状态角标（如座位旁「可胡」）。  
     **验收条件**：与 `steam-shot-2.jpg` 并排时，首眼链路不依赖阅读说明文案即可完成「谁打了什么 → 我能胡」。  
     **禁止扩展**：不新增第二套教学引导 UI；不引入日式术语。
  2. **作用范围**：底部动作层字效与材质  
     **具体改动**：将 `碰/杠/过` 从「深色矩形面板按钮」收敛为接近 Riichi City 的字效/印章式动作层；`胡` 保持唯一最强金光主按钮，面积与亮度显著高于其余；`过` 清晰但低强调。  
     **验收条件**：截图中动作层不再像 Web 工具条；主动作唯一性肉眼无可争议。  
     **禁止扩展**：不把动作层做成侧栏或菜单列表。
  3. **作用范围**：四角座位信息密度  
     **具体改动**：压缩角标/状态标签墙，向竞品「头像 + 分数 + 轻量状态」靠拢；当前出牌家用座位高亮表达，避免多条并列状态文案抢桌心。  
     **验收条件**：桌心主舞台面积观感 ≥ 画面约 55%，角区不形成 Web 侧栏感。  
     **禁止扩展**：不重做整套角色系统或动效片。

## 主要问题
- 严重级别：高  
  维度：冲顶完成度  
  问题：说明型叠加层（大箭头 / 气泡 / 说明条）承担了本应由牌、光效、座位高亮完成的首眼链路。  
  影响：整体更像「带标注的设计交付稿」，而非 Riichi City 式「正在进行的商业局内帧」；不符合竞品级效果图交付。  
  建议：按改稿单第 1 条重绘，禁止继续叠教学层。

- 严重级别：中  
  维度：视觉语义 / 冲顶完成度  
  问题：次级动作仍偏 Web 矩形按钮条，与竞品字效动作层差距明显。  
  影响：即使桌面骨架接近，动作层会把观感拉回产品原型。  
  建议：按改稿单第 2 条收敛。

- 严重级别：中  
  维度：冲顶完成度  
  问题：四角状态文案密度偏高，桌心张力被角区信息分流。  
  影响：首眼不能稳定锁在「目标牌 → 胡」。  
  建议：按改稿单第 3 条减负。
