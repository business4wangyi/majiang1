# 面向非工程读者的沟通规范

> **E0 强制执行** — 解释、设计确认、进度、结论时 **MUST Read**。  
> 受众默认：会玩麻将/棋类、不熟悉本仓库代码的产品或玩家向读者。

## 必须遵守

1. **先讲人话，再讲工程**  
   先说「做什么、为什么、做完玩家/你会多得到什么」；文件路径与函数名默认后置。
2. **中文为主，术语首次解释**  
   如 UI（用户界面）、CLI（命令行界面）、core（核心规则层）等首次出现给中文义。
3. **概念与实现分离**  
   概念层：对局怎么走、界面几块、能不能胡；实现层：具体文件——仅排查/改码时展开。
4. **结论先行**  
   长说明开头 ≤3 条当前结论。
5. **复杂流程优先图/表**  
   见 `mermaid-rules.md`；少写无结构长文。

## 设计确认：决策卡（默认）

对人确认时默认只出**决策卡**（正文建议 ≤200 汉字，图另计）：

1. **结论**：本分叉选什么  
2. **为什么（仅分叉）**：选 A vs B 各怎样  
3. **需你拍板**：无，或 1 个选择题  
4. **风险**：最多 3 条短句  
5. **已批准共识**：一句引用，不复述说明书  

用户回「符合 / 继续」= 批准本卡结论；细节进文档，不要求用户在聊天通读长文。

## UI 层一句话（与交付流程一致）

| 层 | 含义 | 禁止 |
|----|------|------|
| **U0 骨架** | 页面几块、主次、空/错/忙 | 定配色字体当能力波 |
| **U1 能力贴槽** | 往已定槽塞能力 | 整页重排 + 美化混进同一刀 |
| **U2·结构** | 分区/折叠减噪 | 用低保真冒充「好看毕业」 |
| **U2·视觉** | 高保真目标人批后的观感收敛 | 无目标图宣称视觉冲顶通过 |

验级若需写 L1/L2/L3，勿与 U0/U1/U2 混用裸 `L0` 指 UI。

## 抬天花板时

多切片或改整页信息架构时：人审优先批**波次终态**（故事 + 硬不做 + UI 层），不要默认甩每一刀 diff。细则见 `docs/product/delivery-flow.md`。

## 麻将专属硬边界（说明时也要守）

- 前端**不重写**胡/吃/碰/杠判定；只消费核心层结果。  
- 功能自动化通过 ≠ 视觉冲顶通过。  
- 阶段A（设计冻结）与阶段B（实现一致性）不得混验。
