# Git MCP 自动化规则（共享正文）

## 核心原则
在满足条件时，允许自动调用 Git MCP 完成提交，减少手动 Git 操作。

## 自动提交触发标准（AND）
1. 功能完整：用户请求已完整实现。
2. 代码质量：无明显语法/逻辑错误，符合项目规范。
3. 变更规模：建议 1-10 个文件、10-500 行、关联性强。
4. 用户态度：用户未明确拒绝提交。

## 自动提交场景
- 新功能完成
- Bug 修复完成
- 重构完成
- 配置或文档更新完成
- 测试代码补充完成
- 用户明确要求提交
- 阶段性完成并希望保存进度

## 禁止自动提交场景
- 实验性/临时代码、调试代码
- 功能不完整或有明显缺陷
- 大规模高风险架构调整（例如超过约定规模）
- 用户明确拒绝提交
- 已知错误尚未修复

## 推荐执行流程
1. 检查触发条件。
2. 设置工作目录（绝对路径）。
3. 查看仓库状态。
4. 执行提交（仅提交本次相关文件）。
5. 反馈提交结果（commit hash + 简述）。

## 提交消息规范
建议使用 Conventional Commits：
- `feat`, `fix`, `docs`, `style`, `refactor`, `test`, `chore`

格式：`type(scope): subject`

## 安全约束
- 破坏性操作需要显式确认。
- 对 `git clean`、`git reset --hard` 等高风险命令保持严格限制。
- 工作目录必须是目标仓库绝对路径。
